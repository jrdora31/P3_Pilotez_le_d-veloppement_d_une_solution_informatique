## 2. Ce que le livrable attend

La consigne demande un fichier TXT ou PDF contenant le lien vers le repository GitLab ou GitHub. Ce repository doit contenir :

- le code source complet avec un historique de commits structuré ;
- un README détaillé ;
- des scripts de déploiement ;
- un plan de suivi de qualité et maintenance en plusieurs fichiers : `TESTING.md`, `SECURITY.md`, `PERF.md`, `MAINTENANCE.md`.

Dans ce projet, le livrable est organisé dans :

```text
docs/LIVRABLES/
```

- suppression des fichiers appartenant à l'utilisateur ;

- expiration et purge des fichiers expirés.

## 4. README détaillé

Le README détaillé attendu par la consigne ne doit pas seulement lister les fichiers. Il doit permettre à une personne qui ouvre le repository de comprendre rapidement :

- le but du projet ;
- la stack technique ;
- la structure du code ;
- les prérequis ;
- les commandes d'installation ;
- les commandes de lancement ;
- les commandes de tests et de build ;
- l'emplacement des documents de conception et de qualité.

Dans ce dossier de livrables, une version préparatoire du README détaillé est disponible ici :

```text
docs/LIVRABLES/README.md
```

Recommandation pour le dépôt final :

Il est préférable de placer aussi un `README.md` à la racine du repository GitHub. C'est le premier fichier affiché quand l'évaluateur ouvre le dépôt. Le fichier `docs/LIVRABLES/README.md` peut servir de base à copier ou adapter à la racine.

## 5. Scripts de déploiement et d'exécution

La consigne mentionne des "scripts de déploiement". Dans ce projet, il n'y a pas encore de déploiement vers un hébergeur précis, car aucun environnement cible n'est défini.

Les scripts disponibles sont donc les scripts npm permettant d'installer, vérifier, builder et lancer le projet de façon reproductible. Ils sont déclarés dans le `package.json` racine.

Document dédié :

```text
docs/LIVRABLES/SCRIPTS_DEPLOIEMENT.md
```

Scripts principaux :

| Commande | Rôle |
| --- | --- |
| `npm install` | installer les dépendances |
| `npm run backend:dev` | lancer le backend en développement |
| `npm run frontend:dev` | lancer le frontend en développement |
| `npm run backend:test` | lancer les tests unitaires backend |
| `npm run backend:test:e2e` | lancer les tests e2e backend |
| `npm run frontend:test` | lancer les tests frontend |
| `npm run backend:coverage` | générer la couverture backend |
| `npm run frontend:coverage` | générer la couverture frontend |
| `npm run backend:build` | compiler le backend |
| `npm run frontend:build` | compiler le frontend |
| `npm run swagger` | servir la documentation Swagger |
| `npm run openapi:lint` | vérifier le contrat OpenAPI |

Conclusion :

Pour le MVP, les scripts de déploiement correspondent aux scripts de préparation, validation, build et exécution. Un vrai script de déploiement vers un serveur pourra être ajouté plus tard quand l'hébergement cible sera choisi.

## 9. Points à vérifier avant dépôt final

Avant de déposer le lien du repository sur la plateforme, vérifier :

- que la branche finale choisie contient tous les fichiers de `docs/LIVRABLES/` ;
- qu'un README détaillé existe à la racine du repository ou que sa localisation est clairement indiquée ;
- que `docs/LIVRABLES/SCRIPTS_DEPLOIEMENT.md` est présent ;
- que les quatre fichiers qualité sont présents ;
- que `backend/.env` et `frontend/.env` ne sont pas suivis par Git ;
- que `node_modules/`, `coverage/`, `dist/` et `backend/uploads/` ne sont pas suivis ;
- que le projet peut être installé avec `npm install` ;
- que les commandes de test et de build sont documentées ;
- que le lien GitHub est accessible par l'évaluateur.

Commandes utiles :

```bash
git status --short
git log --oneline --decorate --graph --all -n 30
npm run backend:test
npm run frontend:test
npm run backend:build
npm run frontend:build
```
